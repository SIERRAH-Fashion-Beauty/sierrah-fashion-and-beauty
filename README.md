# SIERRAH – Fashion & Beauty

> **Your Style. Your Beauty. Your Way.**

SIERRAH styles what you already own. Pick an occasion, and a Python recommendation engine scores your real wardrobe, builds several different outfits, explains each one, and suggests a purchase only when a look genuinely needs it. Each outfit can then be turned into an AI-generated fashion-model preview through an image provider you configure on the backend: Google Gemini, OpenAI, or the free keyless Pollinations service.

## What is real and what is not

| Part | Status |
|------|--------|
| Wardrobe CRUD, photo upload, Save Wardrobe | Stored in SQLite through the API |
| Recommendations | Scored by the Python engine (`backend/app/services/recommendation`). The wardrobe and preferences you send are what it uses |
| Saved looks | Stored in SQLite as the original recommendation. Reopening one makes no recommendation or image call |
| AI model images | Generated by the provider you configure (Gemini, OpenAI or free Pollinations), from a prompt built from the outfit. **Off until you set `IMAGE_PROVIDER`** (and `IMAGE_API_KEY` for Gemini/OpenAI). Without a key the app says so and shows a sample photo labelled *Sample photo · not AI-generated* |
| Shopping catalog | **Demo data.** Prices, products and "buy" targets are samples, and the UI labels them as demo |

A text-to-image model *interprets* the outfit. It is not an exact virtual try-on, and garments can differ from your photos. Turning on "Use my clothing photos as a visual guide" sends them to `/images/edits`, which improves but does not guarantee fidelity.

## Run it locally (Windows PowerShell)

Prerequisites: **Node.js 20+**, **Python 3.10+**. Use two terminals.

### Terminal 1: backend

```powershell
cd sierrah-fashion-and-beauty\backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

If PowerShell blocks `Activate.ps1`: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`.

API: <http://127.0.0.1:8000>, interactive docs at `/docs`, health at `/health`.

### Terminal 2: frontend

```powershell
cd sierrah-fashion-and-beauty\frontend
npm install
Copy-Item .env.example .env
npm run dev
```

Open **<http://localhost:5173>**.

### Both at once

```powershell
.\scripts\start-all.ps1
```

### Tests and build

```powershell
# backend (from backend\, venv active)
python -m pytest tests -q

# frontend (from frontend\)
npm run build        # type-check + production build
```

### macOS / Linux

```bash
cd backend && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && cp .env.example .env
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

## AI model images

### 0. No key at all: free Pollinations

```
IMAGE_PROVIDER=pollinations
```

That is all (leave `IMAGE_API_KEY` empty) and restart the backend. It uses [Pollinations' free classic API](https://github.com/pollinations/pollinations/blob/master/APIDOCS.md). Verified in this project with live calls (about 10 to 20 seconds per image), with these trade-offs:

- Quality is clearly below Gemini/OpenAI: faces can look smudged and colours or cuts can drift from the outfit.
- Every image carries a small *pollinations.ai* logo in the corner.
- Anonymous free use is limited per IP: **one image at a time, at least about 45 seconds apart**. If you click twice quickly you get "try again in N seconds".
- Best effort, no uptime guarantee, and the terms can change. The model is chosen by the service.
- It cannot use your clothing photos as references, and it receives a short ~300 character version of the prompt (long prompts made the model ignore the outfit).
- Your prompt (outfit items, colours, appearance options) is sent to a third party. No photos and no personal data are sent.

### 1. Get a key (Gemini or OpenAI)

**Google Gemini (recommended here):**

1. Sign in at <https://aistudio.google.com/apikey> and choose **Create API key**.
2. Image generation may need a billing-enabled project or a paid tier; if the API answers with a quota or permission error, check the plan and limits for your key.

**OpenAI (alternative):** create a key at <https://platform.openai.com/api-keys> and add billing. OpenAI's newest image models may require API organization verification.

Image generation is billed or quota-limited per image. `IMAGE_MAX_PER_HOUR` (default 30) caps spend from this backend.

### 2. Put it on the backend only

Edit `backend/.env` (it is git-ignored):

```
IMAGE_PROVIDER=gemini
IMAGE_API_KEY=your-gemini-key
```

(`GEMINI_API_KEY` or `GOOGLE_API_KEY` also work when `IMAGE_API_KEY` is empty.) Restart uvicorn. `GET /health` then reports `imageGeneration.configured: true` with provider `gemini`. The key is never sent to the browser, never written to the database and never logged. Do not put it in `frontend/.env`, because anything prefixed `VITE_` is public.

Gemini options: `IMAGE_MODEL` (default `gemini-nano-banana-2.1`; others listed in Google's [image generation docs](https://ai.google.dev/gemini-api/docs/image-generation), e.g. `gemini-3-pro-image`), `IMAGE_ASPECT_RATIO` (default `2:3`), `IMAGE_RESOLUTION` (default `1K`). Requests are sent with `store: false`. All Gemini images carry Google's SynthID watermark.

To use OpenAI instead: `IMAGE_PROVIDER=openai`, `IMAGE_API_KEY=sk-...`, optionally `IMAGE_MODEL` (default `gpt-image-2.5-flare`), `IMAGE_SIZE`, `IMAGE_QUALITY`.

Common to both: `IMAGE_TIMEOUT_SECONDS`, `IMAGE_MAX_RETRIES`.

### 3. How it behaves

- Look 1 is generated automatically after "Get My Look" if a provider is configured. Other options generate on demand with **Create AI model preview**.
- The prompt is built from the outfit's items, colours, accessories and your *selected* appearance options (skin tone, hair, build, pose). Free-text notes are never copied into the prompt.
- Generation takes roughly 30 to 120 seconds. The UI shows progress, a retry button on failure, and distinct messages for a missing or rejected key, rate limits, moderation blocks and timeouts.
- The result is stored under `MEDIA_DIR` and served from `/media`. A saved look keeps its stored image path; reopening it never calls the provider.
- **Regenerate** makes a fresh call.

### 4. Optional live test

The automated suite never calls a real provider. To try yours once:

```powershell
$env:SIERRAH_LIVE_IMAGE_TEST = "1"
$env:LIVE_IMAGE_PROVIDER = "gemini"     # or "openai" (default)
$env:LIVE_IMAGE_API_KEY = "your-key"
python -m pytest tests/test_live_provider.py -q -s
```

## REST API

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Liveness plus image-provider status |
| GET / POST | `/api/wardrobe` | List / create item |
| PUT / DELETE | `/api/wardrobe/{item_id}` | Update / delete |
| PUT | `/api/wardrobe/sync` | Replace the wardrobe (Save Wardrobe) |
| POST | `/api/recommendations` | Wardrobe + occasion + preferences → scored outfits |
| GET / POST | `/api/saved-looks` | List / save a look |
| PATCH | `/api/saved-looks/{look_id}` | Toggle favourite |
| DELETE | `/api/saved-looks/{look_id}` | Delete |
| GET | `/api/outfits/{outfit_id}` | A stored outfit |
| POST | `/api/outfits/{outfit_id}/generate-image` | Generate (or return the cached) model image |
| GET | `/api/catalog` | Demo shopping catalog |

Errors are JSON. Validation errors use FastAPI's 422 list. Image errors use `{"detail": {"code", "message", "retryable"}}`.

## Recommendation engine

Seven built-in occasions (College, Casual, Office, Wedding, Party, Travel, Festival) plus custom text, which is mapped to the nearest profile by keywords such as "interview" or "engagement". Each candidate outfit gets a 0 to 100 score:

| Factor | Max |
|--------|-----|
| Occasion fit | 35 |
| Colour harmony and your colour choice | 17 |
| Style match | 13 |
| Comfort | 10 |
| Completeness | 15 |
| Budget | 10 |

Outfits that clearly do not suit the occasion are gated out. Every outfit returns its items (each marked *yours* or *suggested*), accessories, makeup, hairstyle, tips, missing items, cheaper alternatives and an explanation. If the wardrobe cannot support the occasion (for example no wedding-appropriate piece), the response says so instead of faking a good match. The budget is treated as an upper bound for purchases.

## Deploy (GitHub Pages + Render)

The frontend is a static site on **GitHub Pages**; the API runs on **Render**. The repository already contains `render.yaml` (Render Blueprint) and `.github/workflows/deploy-frontend.yml` (Pages deploy).

### 1. API on Render

1. Sign in at <https://render.com> with GitHub and allow access to this repository.
2. **New > Blueprint**, pick this repo, branch `main`. Render reads `render.yaml` and proposes a web service named `sierrah-api` (free plan, Singapore). Click **Apply**.
3. Wait for the first deploy to go green, then open `https://<your-service>.onrender.com/health`. It should return `{"status":"ok",...}`. Copy that base URL (no trailing slash).
4. If the URL is not exactly `https://sierrah-api.onrender.com` (the name was taken, Render added a suffix), set the repository variable in step 2 below.
5. Optional AI images with Gemini: Render service > **Environment**: set `IMAGE_PROVIDER=gemini` and add `IMAGE_API_KEY` (a secret). Save to redeploy. With the default `pollinations` provider no key is needed.

`CORS_ORIGINS` in `render.yaml` already allows `https://sierrah-fashion-beauty.github.io`. If your Pages address differs (for example a custom domain), edit that value in Render > Environment.

### 2. Frontend on GitHub Pages

1. Repository **Settings > Pages > Build and deployment > Source: GitHub Actions**.
2. Repository **Settings > Secrets and variables > Actions > Variables > New repository variable**: name `VITE_API_BASE_URL`, value your Render URL. Skip it only if your URL is exactly `https://sierrah-api.onrender.com`.
3. Push to `main` (or **Actions > Deploy frontend to GitHub Pages > Run workflow**). The workflow builds with `VITE_BASE_PATH=/<repo-name>/`, adds a `404.html` fallback and publishes.
4. Open `https://sierrah-fashion-beauty.github.io/sierrah-fashion-and-beauty/`.

Changing the API URL later means updating the variable and re-running the workflow, because `VITE_` values are baked in at build time.

### What to expect on the free tier

- **Cold starts:** a free Render service sleeps after about 15 minutes idle. The first request afterwards takes roughly 30 to 60 seconds; the app shows its "backend not connected" banner with a Retry button until it wakes.
- **Ephemeral data:** the free plan has no persistent disk. The SQLite database and generated images are lost on every restart or redeploy; the demo wardrobe is re-seeded and saved looks disappear. For persistence use a paid plan, attach a disk at `/var/data` and set `DATABASE_PATH=/var/data/sierrah.db`, `MEDIA_DIR=/var/data/media`.
- **Single shared user:** there are no accounts. Everyone who opens the public site shares the same wardrobe and saved looks. Treat it as a demo, and do not store anything private in it.
- **Public API and cost:** anyone can call the API. `IMAGE_MAX_PER_HOUR` caps image generation per server process, which limits the damage if you attach a paid key.
- **Pollinations on Render:** its free limit is per IP and Render's outbound IPs are shared, so "one image at a time" errors can be frequent. Use Gemini or OpenAI for reliable previews.

### Other hosts

Any host that runs `pip install -r requirements.txt` and `uvicorn app.main:app --host 0.0.0.0 --port $PORT` works for the API (set `CORS_ORIGINS`, `DATABASE_PATH`, `MEDIA_DIR` on a persistent disk). Any static host works for the frontend: `cd frontend && npm ci && npm run build`, publish `frontend/dist`, add a single-page-app rewrite (`/* -> /index.html`), and set `VITE_API_BASE_URL` (and `VITE_BASE_PATH` if it is not served from the domain root) at build time.

## Offline behaviour

The wardrobe, saved looks and preferences are cached in `localStorage`. If the API is unreachable, a banner shows and edits are flagged to sync later. **Recommendations and AI images need the backend**: the engine runs in Python, so offline the app shows an error with a retry button rather than inventing results. The offline seed JSON in `frontend/src/data/seed` is generated from the backend data with `python backend/scripts/export_seed_data.py`.

## Known limitations

- The Pollinations provider has been exercised live. No live Gemini or OpenAI call has been exercised in this repository's tests. The Gemini request and response handling follows Google's published docs and is tested with a mock transport and a local fake server only. Run the opt-in live test with your key to confirm it.
- Windows `.ps1` helper scripts are untested. The GitHub Pages build was verified against a local emulation (base path, `404.html` fallback, cross-origin API); the real Render and GitHub Actions runs have not been executed from here.
- Prototype saved looks from the first version are deleted by the schema v1 → v2 migration.
- Saved looks embed wardrobe images at save time, so later edits to an item do not change an old look.
- The demo wardrobe has no sarees, so wedding results rely on kurtis or suggested items unless you add one.
- Single-user: there are no accounts or authentication.
- Product photography in `frontend/public/images` was AI-generated for this prototype and is always labelled as a sample.

## Troubleshooting

- **"Backend not connected":** start the API and click **Retry**.
- **CORS error:** open the app from `http://localhost:5173` or add your origin to `CORS_ORIGINS` and restart.
- **"AI model previews are not set up yet":** add `IMAGE_PROVIDER=pollinations` (free) or `gemini` / `openai` plus `IMAGE_API_KEY` to `backend/.env`, then restart.
- **`CERTIFICATE_VERIFY_FAILED` / "Could not reach the image provider":** usually a corporate TLS-inspection proxy. Run `pip install -r requirements.txt` (adds `truststore`) and keep `IMAGE_USE_SYSTEM_CA=true`.
- **Free image says "one image at a time":** wait the number of seconds shown, then press Try again.
- **Image says the key was rejected:** check the key, that the Gemini API is enabled for it, and billing/organization verification (OpenAI).
- **Start fresh:** Profile → *Reset demo data*, or delete `backend/data/sierrah.db` and clear site data.
